# Spec Delta

## Purpose

讓使用者從已核實商品出發，取得可審閱的繁體中文貼文與授權素材短片，並能逐組修改、恢復失敗及控制確認匯出。

## ADDED Requirements

### Requirement: 使用者內容偏好可設定
系統 MUST 讓使用者設定分享對象、內容主題、繁體中文語氣及預設風格，並允許使用者日後修改；每次生成使用當下的偏好版本。

#### Scenario: 首次設定內容偏好
- **GIVEN** 使用者尚未設定內容偏好
- **WHEN** 使用者開始建立內容批次
- **THEN** 系統提供偏好設定與可修改的預設值，且不要求使用者為每個商品重新填寫相同設定

#### Scenario: 更新偏好後建立批次
- **GIVEN** 使用者已更新分享對象、主題或預設風格
- **WHEN** 使用者啟動新批次
- **THEN** 系統使用最新偏好生成內容，並保留該批次所用偏好版本

### Requirement: 批次建立配套內容
系統 MUST 支援每批最多 3 個可製作商品、每商品 2 個敘事版本；每個商品版本建立唯一內容組，包含一則貼文及一支對應短片。

#### Scenario: 建立最大批次
- **GIVEN** 使用者選取 3 個就緒商品並選擇每個商品的 2 個版本
- **WHEN** 使用者啟動製作
- **THEN** 系統建立 6 個唯一內容組，且每組貼文與短片均對應正確商品及版本

#### Scenario: 超過批次上限
- **GIVEN** 使用者已選取 3 個商品
- **WHEN** 使用者嘗試將更多商品加入同一批
- **THEN** 系統拒絕超出上限的選取並保留已選商品

### Requirement: 商品主張以已核實事實為限
系統 MUST 僅依商品的可追溯資料產生貼文、腳本、旁白及字幕，不得捏造規格、功效、優惠、親身體驗或收益保證。

#### Scenario: 生成有來源的商品內容
- **GIVEN** 商品有一組有限且已核實的事實
- **WHEN** 系統產生貼文、腳本、旁白及字幕
- **THEN** 各輸出只陳述有來源支持的商品事實，且能追溯使用的資料版本

#### Scenario: 缺少支持特定主張的資料
- **GIVEN** 商品資料沒有支持某項規格、功效或使用經驗
- **WHEN** 系統產生內容
- **THEN** 系統不得加入該主張，也不得以其他商品的資料補足

### Requirement: 使用原商品的授權素材
系統 MUST 使用權利已核實且對應所選商品的圖片或影片製作短片，保留商品真實外觀及必要文字，不得生成替代實物畫面。

#### Scenario: 以核准素材剪輯
- **GIVEN** 商品有可用且權利涵蓋剪輯與匯出的素材
- **WHEN** 系統製作短片
- **THEN** 短片使用該商品素材並保留可辨識商品的必要特徵與文字，且每項素材可追溯來源

#### Scenario: 缺少可用視覺素材
- **GIVEN** 商品沒有權利已核實的圖片或影片
- **WHEN** 系統製作短片
- **THEN** 系統阻擋該內容組並說明原因，不得生成替代商品畫面

### Requirement: 輸出指定的短片格式
系統 MUST 為每組內容提供可播放的 15–30 秒、1080×1920 直式 MP4，含繁體中文字幕及可辨識配音。

#### Scenario: 成功輸出短片
- **GIVEN** 商品腳本與素材通過製作前檢查
- **WHEN** 短片渲染完成
- **THEN** 使用者可預覽符合指定長度、尺寸及格式的影片，字幕未裁切且配音與畫面無重大不同步

#### Scenario: 影音輸出不合格
- **GIVEN** 渲染結果無法播放、格式不符、字幕被裁切或有重大不同步
- **WHEN** 系統完成輸出檢查
- **THEN** 系統將該組標示為失敗或待修正，不得呈現為可確認匯出

### Requirement: 可逐組預覽與修改
系統 MUST 讓使用者預覽每組貼文與短片，並可修改文字、選擇預設風格或單獨重生成；修改須更新該組對應內容且不改動其他組。

#### Scenario: 修改單一組內容
- **GIVEN** 批次中有多組已完成內容
- **WHEN** 使用者修改其中一組文字或風格
- **THEN** 系統只更新該組的相關輸出，並保留其他組及其狀態

#### Scenario: 單組重新生成
- **GIVEN** 使用者選擇重新生成一組內容
- **WHEN** 系統完成重生成
- **THEN** 新輸出仍對應原商品與版本，保留原始及新版本的狀態紀錄，且其他組不重做

### Requirement: 局部失敗可安全恢復
系統 MUST 以批次及內容組識別製作請求，使單組失敗可重試而不重複建立或重複計算其他成功組；重試相關成本須納入紀錄。

#### Scenario: 重試逾時的單組
- **GIVEN** 一組內容逾時而同批其他組已完成
- **WHEN** 使用者重試失敗組
- **THEN** 系統只重試該組、保留成功組，並將重試成本與結果記入原內容組

#### Scenario: 重複提交請求
- **GIVEN** 同一批製作請求因重送而再次送達
- **WHEN** 系統處理重複請求
- **THEN** 系統不建立重複內容組，也不重複記錄確認或計費事件

### Requirement: 確認後才可匯出
系統 MUST 要求使用者預覽並確認合格內容後才提供下載，並提供分潤關係揭露位置；系統不得自動發布。

#### Scenario: 未確認時嘗試匯出
- **GIVEN** 內容尚未經使用者確認
- **WHEN** 使用者嘗試匯出
- **THEN** 系統阻擋匯出並要求先完成預覽與確認

#### Scenario: 確認內容並匯出
- **GIVEN** 商品、素材權利及影音輸出檢查仍有效，且使用者已預覽並確認
- **WHEN** 使用者匯出該組內容
- **THEN** 系統提供可下載的貼文與短片，顯示分潤關係揭露位置，並保留確認與匯出紀錄而不發布內容
